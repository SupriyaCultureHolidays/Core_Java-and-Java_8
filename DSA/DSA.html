Two Pointer

Two Pointer হলো DSA-র একটা খুবই গুরুত্বপূর্ণ Pattern — মূলত Array এবং String-এর Problem Solve করতে ব্যবহার হয়। সহজ কথায়: একটা Array/String-এর উপর কাজ করার জন্য দুটো Index (Pointer) ব্যবহার করা হয়, যাতে বারবার একই Element Check না করে কম সময়ে Solution বের করা যায়।

কেন Two Pointer ব্যবহার করি

ধরো একটা Array আছে [1, 2, 3, 4, 5]। সব Pair Check করতে চাইলে (1-এর সাথে সবাই, 2-এর সাথে সবাই...) Nested Loop লাগবে। কিন্তু Two Pointer ব্যবহার করলে অনেক ক্ষেত্রেই একই কাজ কম সময়ে হয়ে যায়।

ApproachTime Complexity
Nested Loop (Brute Force)O(n²)
Two PointerO(n)

Two Pointer-এর প্রধান ৩টা Pattern

১) Slow & Fast Pointer — একই দিকে এগোয়

দুটো Pointer একই Direction-এ (বাম থেকে ডানে) এগোয়। i (Slow) এখন পর্যন্ত পাওয়া Unique জায়গা ধরে রাখে, j (Fast) পুরো Array ঘুরে দেখে।

Remove Duplicate — Dry Run
Array: [1, 1, 2, 2, 3]

i = 0, j = 1  →  nums[i]=1, nums[j]=1  →  Same, কিছু করার নেই
j++           →  nums[i]=1, nums[j]=2  →  Different  →  i++, nums[i] = nums[j]
              →  Array হয়ে যায়: [1, 2, 2, 2, 3]
              →  প্রথম দুটো ঘর এখন Unique: [1, 2]

কোথায় ব্যবহার হয়: Remove Duplicates, Remove Element, Move Zeroes, Array Compression

২) Left & Right Pointer — দুই প্রান্ত থেকে

একটা Pointer শুরুতে (left), আরেকটা শেষে (right) থাকে — দুজন একে অপরের দিকে এগোয়।

Reverse Array
[1, 2, 3, 4, 5]

1 ↔ 5  →  [5, 2, 3, 4, 1]
2 ↔ 4  →  [5, 4, 3, 2, 1]

কোথায় ব্যবহার হয়: Reverse Array, Palindrome Check, Two Sum (Sorted Array), Container With Most Water

৩) Sliding Window — Two Pointer-এর Advanced রূপ

দুটো Pointer মিলে একটা "Window" বানায় — দরকারমতো বড় বা ছোট হয়।

Window বড়/ছোট হওয়া
[1, 2, 3, 4, 5]

L R
[1, 2]        ← Window ছোট

L     R
[1, 2, 3]     ← Window বড় হলো

   L  R
   [2, 3]     ← দরকার হলে আবার ছোট হলো

কোথায় ব্যবহার হয়: প্রশ্নে "Longest / Smallest / Maximum / Minimum Subarray বা Substring" থাকলে — যেমন "Longest Substring Without Repeating Characters"

কীভাবে বুঝবে কোন Pattern লাগবে

  1. Array কি Sorted? → Two Pointer Try করো
  2. In-place Change করতে হবে (নতুন Array বানানো যাবে না)? → Slow-Fast Pointer
  3. Pair খুঁজতে হবে (Sorted Array-তে)? → Left-Right Pointer
  4. Continuous অংশ (Subarray/Substring) খুঁজতে হবে? → Sliding Window

Interview Rule: Array/String দেখলেই আগে ভাবো — Sorted? → Two Pointer। In-place? → Slow-Fast। Pair? → Left-Right। Subarray/Substring? → Sliding Window।

            arr[i] = sc.nextInt();
        }

Java-তে String একটি Class, Primitive নয় — এবং এটি Immutable (একবার তৈরি হলে বদলানো যায় না)। ভেতরে এটি আসলে একটি char[]-এর উপর তৈরি, কিন্তু char[]-এর মতো সরাসরি index দিয়ে বদলানো যায় না।

String s = "hi";
// s.charAt(0) = 'H';  ❌ এভাবে বদলানো যায় না
s = "Hi";   // নতুন String তৈরি হয়

সবচেয়ে বড় ভুল ধারণা: Binary Search মানে শুধু "Sorted Array-তে Search করা" নয়। বাস্তবে Interview-এর ৮০% Binary Search Question আসলে Binary Search on Answer বা Monotonic Property-এর উপর ভিত্তি করে।

Binary Search প্রতিবার Search Space-কে অর্ধেক করে ফেলে, তাই কাজ হয় O(log n)-এ। এটা কাজ করার একমাত্র শর্ত — Array Sorted হতে হবে, বা এমন একটা Monotonic Property থাকতে হবে যেখানে একটা Point-এর আগে সব কিছু এক রকম, পরে আরেক রকম।

Classic Binary Search — Formula
int low = 0;
int high = arr.length - 1;

while (low <= high) {
    int mid = low + (high - low) / 2;   // Overflow-safe — (low+high)/2 লিখলে বড় Array-তে Overflow হতে পারে

    if (arr[mid] == target) {
        return mid;
    } else if (arr[mid] < target) {
        low = mid + 1;
    } else {
        high = mid - 1;
    }
}
Interview Tip: সবসময় mid = low + (high - low) / 2 লিখবে, (low + high) / 2 নয় — এটা Interviewer-কে দেখায় Integer Overflow সম্পর্কে সচেতন আছো।

canDo(mid) — এই Pattern-এর আসল Heart
int low = minimumPossible;
int high = maximumPossible;

while (low <= high) {
    int mid = low + (high - low) / 2;

    if (canDo(mid)) {
        high = mid - 1;   // অথবা low = mid + 1 — Problem অনুযায়ী ঠিক করবে
    } else {
        low = mid + 1;
    }
}

Recursion

আগে Array ও String-এর Basic Problem শেষ করে এসো। Recursion-এর অনেক Problem আসলে Array/String-এর উপরেই হয় — এবং Recursion ঠিকভাবে শিখলে পরে Tree, Backtracking ও Dynamic Programming অনেক সহজ লাগবে।

Recursion মানে — একটি Function নিজেই নিজেকে Call করে। প্রতিটা Recursive Function-এ দুটো অংশ থাকতেই হয়: একটা Base Case (যেখানে থেমে যায়) এবং একটা Recursive Case (যেখানে নিজেকে আবার Call করে, কিন্তু ছোট Input নিয়ে)।

Factorial — Base Case + Recursive Case
int factorial(int n) {
    if (n == 0) return 1;        // Base Case — এখানে থেমে যায়
    return n * factorial(n - 1); // Recursive Case — ছোট Input নিয়ে নিজেকে Call করে
}

Call Stack — Recursion Memory-তে কীভাবে কাজ করে

প্রতিটা Recursive Call-এর জন্য একটা নতুন Stack Frame তৈরি হয়, ঠিক সাধারণ Method Call-এর মতোই। যতক্ষণ Base Case না পাওয়া যায়, ততক্ষণ নতুন Frame Push হতেই থাকে — তারপর Base Case থেকে একে একে Frame Pop হয়ে Result উপরে ফেরত যায়।

CALL STACK — factorial(3)
▲ factorial(0) ← সবার শেষে Push, সবার আগে Pop (Base Case)
return=1
factorial(1)
n=1// অপেক্ষায় — 1 * factorial(0)
factorial(2)
n=2// অপেক্ষায় — 2 * factorial(1)
▼ factorial(3) ← সবার আগে Push, সবার শেষে Pop

Unwind — Base Case থেকে ফেরত আসা

= 3 * (2 * (1 * 1))

Stack Overflow

Base Case না থাকলে বা ভুল Base Case লিখলে Function নিজেকে থামা ছাড়াই Call করতে থাকে — প্রতিটা Call-এর জন্য নতুন Frame Push হয়, একসময় Stack ভরে গিয়ে Error আসে।

Base Case ছাড়া — ভুল Recursion
int badRecursion(int n) {
    return badRecursion(n - 1);   // Base Case নেই — কখনো থামবে না
}

// Exception in thread "main" java.lang.StackOverflowError
নিয়ম: Base Case সবসময় সবার আগে লেখো, এবং নিশ্চিত করো প্রতিটা Recursive Call যেন Base Case-এর দিকে এগিয়ে যায় (যেমন n ছোট হতে হতে 0-তে পৌঁছাবে)।

Linked List

Recursion না শিখে এখানে এসো না। Linked List-এর অনেক Solution (Reverse, Merge, Recursive Traversal) Recursion-এর উপর নির্ভর করে। তবে প্রথমে Iterative Solution শিখবে, তারপর Recursive।

Linked List হলো একগুচ্ছ Node-এর Chain — প্রতিটা Node-এ থাকে Data এবং পরের Node-এর ঠিকানা (next)। Array-এর মতো Continuous Memory লাগে না — প্রতিটা Node Heap-এর যেকোনো জায়গায় থাকতে পারে, শুধু next দিয়ে একটার সাথে আরেকটা জোড়া লাগানো থাকে।

Node — Linked List-এর একক
class Node {
    int data;
    Node next;

    Node(int data) {
        this.data = data;
        this.next = null;
    }
}
তিনটে Node জোড়া লাগানো
Node head = new Node(10);
head.next = new Node(20);
head.next.next = new Node(30);

// Traverse এবং Print
Node temp = head;
while (temp != null) {
    System.out.print(temp.data + " → ");
    temp = temp.next;
}
System.out.println("null");   // 10 → 20 → 30 → null
HEAP — Node গুলো ছড়িয়ে ছিটিয়ে, next দিয়ে জোড়া লাগানো
Node 1 (Head)
data=10
next=ref →
Node 2
data=20
next=ref →
Node 3 (Tail)
data=30
next=null
Head মানে প্রথম Node-এর Reference — এটা হারিয়ে গেলে পুরো Linked List হারিয়ে যায়। Tail মানে শেষ Node, যার next সবসময় null।

গুরুত্বপূর্ণ Pattern ১ — Slow & Fast Pointer

Middle Node খুঁজতে বা Loop Detect করতে সবচেয়ে ব্যবহৃত Pattern। slow এক ঘর করে এগোয়, fast দুই ঘর করে — fast শেষে পৌঁছালে slow ঠিক Middle-এ থাকে।

Middle Node খোঁজা
Node slow = head, fast = head;

while (fast != null && fast.next != null) {
    slow = slow.next;         // ১ ঘর
    fast = fast.next.next;    // ২ ঘর
}
// fast শেষে পৌঁছালে slow মাঝখানে
Floyd's Cycle Detection: একই Slow-Fast Pointer দিয়ে Loop আছে কিনা বোঝা যায় — Loop থাকলে fast কোনো একসময় ঘুরে এসে slow-কে ধরে ফেলবে (slow == fast)।

গুরুত্বপূর্ণ Pattern ২ — Reverse Linked List (Iterative)

সবচেয়ে বেশি জিজ্ঞেস করা Interview Question। তিনটে Pointer লাগে — prev, curr, next।

prev / curr / next — তিনটে Pointer
Node prev = null;
Node curr = head;

while (curr != null) {
    Node next = curr.next;   // পরের Node হারিয়ে যাওয়ার আগে ধরে রাখো
    curr.next = prev;        // Link উল্টে দাও
    prev = curr;              // prev এগিয়ে যাক
    curr = next;              // curr এগিয়ে যাক
}

head = prev;   // নতুন Head এখন শেষের Node

Stack একটা Data Structure যেটা LIFO (Last In First Out) নিয়মে চলে — সবচেয়ে শেষে যেটা রাখা হয়েছে, সেটাই সবার আগে বের হয়। প্লেটের Stack-এর মতো — উপরের প্লেটটাই সবার আগে সরানো হয়।

Java-তে Stack — Core Operations

push / pop / peek / isEmpty
Stack<Integer> stack = new Stack<>();

stack.push(10);       // Push — উপরে যোগ করা
stack.push(20);
stack.push(30);

stack.pop();          // Pop — উপরেরটা সরানো ও ফেরত দেওয়া (30)
stack.peek();         // Peek — উপরেরটা দেখা, সরানো হয় না (20)
stack.isEmpty();      // Empty Check — true/false

Pattern ১ — DFS Traversal (Preorder / Inorder / Postorder)

তিনটেই Recursion দিয়ে হয়, শুধু Root Print করার জায়গাটা বদলায়। Preorder — Root → Left → Right। Inorder — Left → Root → Right (BST-এ Inorder করলে Sorted Order পাওয়া যায়)। Postorder — Left → Right → Root।

তিনটে Recursive Traversal
void preorder(TreeNode root) {
    if (root == null) return;
    System.out.print(root.val + " ");   // Root আগে
    preorder(root.left);
    preorder(root.right);
}

void inorder(TreeNode root) {
    if (root == null) return;
    inorder(root.left);
    System.out.print(root.val + " ");   // Root মাঝখানে
    inorder(root.right);
}

void postorder(TreeNode root) {
    if (root == null) return;
    postorder(root.left);
    postorder(root.right);
    System.out.print(root.val + " ");   // Root সবার শেষে
}
Inorder — Iterative (Stack দিয়ে)
List<Integer> inorderIterative(TreeNode root) {
    List<Integer> result = new ArrayList<>();
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode curr = root;

    while (curr != null || !stack.isEmpty()) {
        while (curr != null) {          // যতদূর Left যাওয়া যায়
            stack.push(curr);
            curr = curr.left;
        }
        curr = stack.pop();             // এটাই এখন Visit করার Node
        result.add(curr.val);
        curr = curr.right;              // এবার Right-এ যাও
    }
    return result;
}
মনে রাখো: Recursive Solution সবসময় Call Stack ব্যবহার করে (Implicit Stack) — Iterative Solution-এ সেটাই তুমি নিজে Deque দিয়ে Explicit করছ।

Pattern ২ — BFS / Level Order Traversal

Queue দিয়ে Level ধরে ধরে ঘোরা হয়। প্রতিটা Level শুরু করার আগে queue.size() ধরে রাখলে বোঝা যায় ঠিক কতগুলো Node এই Level-এ আছে।

Level Order Traversal
List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> result = new ArrayList<>();
    if (root == null) return result;

    Queue<TreeNode> queue = new LinkedList<>();
    queue.offer(root);

    while (!queue.isEmpty()) {
        int size = queue.size();        // এই Level-এ কতগুলো Node
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
            TreeNode node = queue.poll();
            level.add(node.val);
            if (node.left != null)  queue.offer(node.left);
            if (node.right != null) queue.offer(node.right);
        }
        result.add(level);
    }
    return result;
}
এই size ধরে রাখার Trick-টাই Zigzag, Right/Left View, Average of Levels — সব Level-ভিত্তিক Problem-এর ভিত্তি।

Pattern ৩ — Height / Depth

Height/Depth-এর প্রতিটা Problem একই আকারে — নিজের Left আর Right Subtree-র Answer নিয়ে, তার সাথে 1 যোগ করে নিজের Answer বানানো (Bottom-Up)।

Maximum Depth
int maxDepth(TreeNode root) {
    if (root == null) return 0;                              // Base Case
    return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}
Diameter of Binary Tree — Height বের করার সময়ই Diameter Update
int diameter = 0;

int height(TreeNode node) {
    if (node == null) return 0;
    int left  = height(node.left);
    int right = height(node.right);
    diameter = Math.max(diameter, left + right);   // এই Node দিয়ে যাওয়া দীর্ঘতম Path
    return 1 + Math.max(left, right);
}
Diameter মানে Root দিয়ে যেতেই হবে এমন কথা নেই — যেকোনো দুটো Node-এর মধ্যে দীর্ঘতম Path। তাই প্রতিটা Node-এ left + right Check করেই Global Maximum রাখা হয়।

Pattern ৪ — LCA (Lowest Common Ancestor)

p আর q — দুটো Node-এর সবচেয়ে কাছের Common Ancestor। Bottom-Up Recursion — যদি p Left-এ পাওয়া যায় আর q Right-এ, তাহলে বর্তমান Node-ই LCA।

LCA in Binary Tree
TreeNode lca(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) return root;

    TreeNode left  = lca(root.left, p, q);
    TreeNode right = lca(root.right, p, q);

    if (left != null && right != null) return root;   // দুই পাশে দুজন — এটাই LCA
    return left != null ? left : right;                 // দুজনেই এক পাশে
}
BST হলে সহজ হয়ে যায়: p.val আর q.val-এর সাথে root.val তুলনা করেই বোঝা যায় LCA বাম না ডানে, নাকি বর্তমান Node-ই — Recursion লাগেই না, Iterative-ও করা যায়।

Pattern ৫ — BST Operations

Search + Validate BST
TreeNode searchBST(TreeNode root, int val) {
    if (root == null || root.val == val) return root;
    return val < root.val ? searchBST(root.left, val) : searchBST(root.right, val);
}

boolean isValidBST(TreeNode node, long min, long max) {
    if (node == null) return true;
    if (node.val <= min || node.val >= max) return false;
    return isValidBST(node.left, min, node.val) && isValidBST(node.right, node.val, max);
}
// প্রথম Call: isValidBST(root, Long.MIN_VALUE, Long.MAX_VALUE)
ভুল যেটা বেশি হয়: শুধু node.left.val < node.val < node.right.val Check করলে হবে না — পুরো Left Subtree-এর প্রতিটা Value node.val-এর চেয়ে ছোট হতে হবে, শুধু সরাসরি Child না। তাই min/max Range নিচে পাঠাতে হয়।

Pattern ৬ — Construction (Traversal থেকে Tree বানানো)

Preorder-এর প্রথম Element সবসময় Root। Inorder-এ সেই Root-এর বাম দিকের অংশ পুরো Left Subtree, ডান দিকের অংশ পুরো Right Subtree — এই দুটো Fact দিয়েই পুরো Tree Recursively বানানো যায়।

Postorder থেকে বানালে Root থাকে সবার শেষে — তাই Postorder-এর Array-টা পেছন থেকে পড়তে হয়। দ্রুত Index বের করতে HashMap-এ Inorder-এর Value → Index রাখা হয়, তাহলে প্রতিবার Linear Search করতে হয় না।

Pattern ৭ ও ৮ — Tree Modification

Invert Binary Tree
TreeNode invertTree(TreeNode root) {
    if (root == null) return null;

    TreeNode temp = root.left;
    root.left  = invertTree(root.right);
    root.right = invertTree(temp);
    return root;
}
Serialize/Deserialize: Preorder-এ Traverse করে null-কেও একটা Marker (যেমন "#") হিসেবে String-এ লিখে রাখলে, সেই String থেকে আবার হুবহু একই Tree ফিরিয়ে আনা যায় — কারণ null Marker গুলোই বলে দেয় কোথায় Left/Right Subtree শেষ।

Pattern ৯ — View Problems

বেশিরভাগ View Problem-এর মূলে থাকে Horizontal Distance (HD) — Root-এর HD 0, Left-এ গেলে -1, Right-এ গেলে +1। এই HD ধরে রাখলেই Top/Bottom/Vertical View বের হয়ে যায়।

Pattern ১ — Basic Trie (Insert / Search / StartsWith)

TrieNode + Insert + Search + StartsWith
class TrieNode {
    TrieNode[] children = new TrieNode[26];
    boolean isEndOfWord = false;
}

class Trie {
    TrieNode root = new TrieNode();

    void insert(String word) {
        TrieNode node = root;
        for (char c : word.toCharArray()) {
            int idx = c - 'a';
            if (node.children[idx] == null) {
                node.children[idx] = new TrieNode();   // এই Character এখনো নেই, নতুন Node বানাও
            }
            node = node.children[idx];
        }
        node.isEndOfWord = true;   // Word এখানে শেষ হয়েছে, মনে রাখো
    }

    boolean search(String word) {
        TrieNode node = find(word);
        return node != null && node.isEndOfWord;   // পুরো Word হিসেবেই আছে কিনা
    }

    boolean startsWith(String prefix) {
        return find(prefix) != null;   // Prefix হিসেবে থাকলেই যথেষ্ট
    }

    private TrieNode find(String s) {
        TrieNode node = root;
        for (char c : s.toCharArray()) {
            int idx = c - 'a';
            if (node.children[idx] == null) return null;
            node = node.children[idx];
        }
        return node;
    }
}
search() vs startsWith() — এখানেই আসল পার্থক্য: দুটোই একই পথ ধরে find() করে, কিন্তু search() শেষে isEndOfWord Check করে (পুরো Word), আর startsWith() করে না (শুধু Path থাকলেই হলো)।

Pattern ২ — Prefix Search

যেকোনো "Prefix", "Autocomplete", "Starts With" Keyword দেখলেই Trie-তে Root থেকে সেই Prefix পর্যন্ত হেঁটে যাওয়ার কথা ভাবো — সেই Node থেকে DFS করলেই ওই Prefix দিয়ে শুরু হওয়া সব Word পাওয়া যায়।

Pattern ৩ — Word Search (DFS + Trie)

Grid-এর মধ্যে একসাথে অনেক Word খুঁজতে হলে প্রতিটা Word আলাদাভাবে খোঁজার বদলে সব Word একটা Trie-তে Insert করে, Grid-এর উপর একবার DFS চালিয়ে Trie-এর সাথে মিলিয়ে মিলিয়ে এগোনো হয় — এতে Common Prefix-ওয়ালা Word গুলোর জন্য বারবার একই কাজ করতে হয় না।

Pattern ৫ — XOR Trie (Advanced)

Heap

Heap মানেই বেশিরভাগ Interview-তে আসলে "Top-K Pattern"। অনেকে শুধু Heap Implement (Array দিয়ে Heapify) শিখেই থেমে যায় — কিন্তু Java Backend Interview-তে তোমাকে PriorityQueue ব্যবহার করে Efficient Solution দিতে পারা বেশি গুরুত্বপূর্ণ।

Heap হলো একটা বিশেষ Complete Binary Tree (Trees Section-এ শেখা), যেখানে প্রতিটা Parent-এর সাথে তার Child-দের একটা নিয়ম মানতে হয় — Max Heap-এ Parent সবসময় Child-দের চেয়ে বড়, Min Heap-এ Parent সবসময় Child-দের চেয়ে ছোট। Java-তে Heap নিজে Implement করতে হয় না — সরাসরি PriorityQueue ব্যবহার করা যায়, যেটার ভেতরেই Heap বসানো আছে।

একটা Min Heap
        2
       / \
      5   3
     / \   \
    9   8   7
লক্ষ্য করো — এটা কোনো Sorted Tree না (BST না)। শুধু নিয়ম এটুকুই: প্রতিটা Parent তার নিজের দুই Child-এর চেয়ে ছোট (Min Heap)। Sibling দুটোর মধ্যে কোনো Order থাকার দরকার নেই।

Array দিয়ে Heap — Index-এর হিসাব

Heap সবসময় একটা Complete Binary Tree বলে, Pointer (left/right) ছাড়াই শুধু একটা সাধারণ Array দিয়ে পুরো Tree Represent করা যায়।

সম্পর্কIndex i-এর Formula
Parent(i - 1) / 2
Left Child2*i + 1
Right Child2*i + 2
Heapify মানে — একটা Node-কে তার সঠিক জায়গায় বসানো। Insert করলে নতুন Element একদম শেষে বসে, তারপর Parent-এর সাথে তুলনা করে করে উপরে ওঠে (Sift-Up)। Delete (সবসময় Root-এর) করলে শেষ Element Root-এ বসিয়ে দিয়ে, নিচের দিকে ঠিক জায়গা খুঁজে নামানো হয় (Sift-Down)। Build Heap মানে গোটা Array-কে একবারে Heap বানানো — শেষ Non-Leaf Node থেকে শুরু করে Root পর্যন্ত পেছন দিকে Heapify করলে O(n)-এই হয়ে যায় (প্রতিটা Element আলাদা Insert করলে যেটা O(n log n) লাগত)।

Java PriorityQueue — Core Operations

Min Heap (Default) ও Max Heap
PriorityQueue<Integer> minHeap = new PriorityQueue<>();                          // Default — Min Heap
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());  // Max Heap

minHeap.offer(10);     // Insert — O(log n)
minHeap.poll();        // সবচেয়ে ছোট/বড়টা Remove করে Return করে — O(log n)
minHeap.peek();        // শুধু দেখা, সরানো হয় না — O(1)
minHeap.isEmpty();     // খালি কিনা
Custom Comparator — Pair/Array Heap
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);  // দ্বিতীয় Value অনুযায়ী ছোট থেকে বড়
pq.offer(new int[]{5, 2});
pq.offer(new int[]{3, 8});
pq.peek();   // {5, 2} — কারণ 2 < 8
নিজের Class বা record ব্যবহার করলে Comparator-এ সেই Object-এর যেকোনো Field দিয়ে Order ঠিক করা যায় — শুধু int[]/Integer-এই আটকে থাকতে হবে না।
OperationTime Complexity
offer() (Insert)O(log n)
poll() (Remove)O(log n)
peek()O(1)
Build Heap (সবগুলো একসাথে)O(n)

Pattern ১ — Top K ⭐⭐⭐⭐⭐

Heap-এর সবচেয়ে গুরুত্বপূর্ণ Pattern। মূল Trick — K Largest খুঁজতে Min Heap রাখো Size k-এ বেঁধে; Heap-এর Size k ছাড়িয়ে গেলেই সবচেয়ে ছোটটা ফেলে দাও, শেষে Heap-এর Top-ই তোমার Kth Largest।

Kth Largest Element — Min Heap আকারে k
int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();

    for (int num : nums) {
        minHeap.offer(num);
        if (minHeap.size() > k) {
            minHeap.poll();          // সবচেয়ে ছোটটা বাদ — বড় k-টাই Heap-এ রাখো
        }
    }
    return minHeap.peek();          // এখন Heap-এর Top-ই Kth Largest
}
উল্টো দিকেও কাজ করে: K Smallest খুঁজতে হলে Max Heap Size k-এ রাখো — যুক্তি ঠিক উল্টো।

Pattern ২ — Merge Pattern ⭐⭐⭐⭐⭐

k-টা আলাদা Sorted List/Array মেলাতে হলে, প্রতিটার প্রথম Element একসাথে একটা Heap-এ রাখো। Heap থেকে সবচেয়ে ছোটটা তোলো, Result-এ যোগ করো, আর সেই একই List-এর পরের Element Heap-এ ঢোকাও — এভাবে সবসময় Heap-এ ঠিক k-টা Element থাকে।

Merge K Sorted Lists — Heap-এ ListNode রাখা
ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> a.val - b.val);

    for (ListNode node : lists) {
        if (node != null) pq.offer(node);   // প্রতিটা List-এর প্রথম Node
    }

    ListNode dummy = new ListNode(-1), tail = dummy;
    while (!pq.isEmpty()) {
        ListNode smallest = pq.poll();
        tail.next = smallest;
        tail = tail.next;
        if (smallest.next != null) pq.offer(smallest.next);   // একই List-এর পরের Node ঢোকাও
    }
    return dummy.next;
}

Pattern ৩ — Stream Problems (Two Heaps) ⭐⭐⭐⭐⭐

Data ক্রমাগত আসতে থাকলে (Stream) পুরোটা প্রতিবার Sort করা যায় না। Find Median from Data Stream-এর মূল Trick — দুটো Heap দিয়ে সংখ্যাগুলোকে সমান দুই ভাগে ভাগ করে রাখা: ছোট অর্ধেকের জন্য Max Heap, বড় অর্ধেকের জন্য Min Heap। দুটোর Top মিলিয়েই Median বেরিয়ে আসে।

Two Heaps দিয়ে Median বের করা
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder()); // ছোট অর্ধেক
PriorityQueue<Integer> minHeap = new PriorityQueue<>();                           // বড় অর্ধেক

void addNum(int num) {
    maxHeap.offer(num);
    minHeap.offer(maxHeap.poll());              // ছোট অর্ধেকের Maximum-টা বড় অর্ধেকে পাঠাও

    if (minHeap.size() > maxHeap.size()) {
        maxHeap.offer(minHeap.poll());          // Size Balance রাখো (সমান বা maxHeap ১ বেশি)
    }
}

double findMedian() {
    if (maxHeap.size() > minHeap.size()) return maxHeap.peek();
    return (maxHeap.peek() + minHeap.peek()) / 2.0;
}
এই Pattern-এর নাম মনে রাখার শর্টকাট: "Stream" → Two Heaps (একটা Max Heap ছোট অর্ধেকের জন্য, একটা Min Heap বড় অর্ধেকের জন্য)।

Pattern ৪ — Closest Problems

Origin/Target থেকে Distance বের করে সেই Distance অনুযায়ী একটা Heap (সাধারণত Max Heap Size k-এ বেঁধে) রাখলেই k-টা Closest Element পাওয়া যায় — Top-K-এরই একটা Variation, শুধু Comparator Distance দিয়ে হয়।

Pattern ৫ — Scheduling ⭐⭐⭐⭐

Meeting/Task-এর End Time বা Available Time একটা Min Heap-এ রাখলে, সবসময় সবচেয়ে আগে ফাঁকা হওয়া Room/CPU বের করা যায় O(log n)-এ।

Pattern ৬ — Greedy + Heap

প্রতি ধাপে সবচেয়ে ছোট (বা সবচেয়ে বড়) দুটো Element নিয়ে কিছু একটা করে আবার Heap-এ ফেরত দেওয়ার দরকার হলে (যেমন দুটো Rope জোড়া লাগানো) সেটাই Greedy + Heap — প্রতিটা ধাপে Local সবচেয়ে ভালো Choice নিলে Global Optimal Cost পাওয়া যায়।

Pattern ৭ — Matrix + Heap

প্রতিটা Row (বা Column) আগে থেকে Sorted থাকা একটা Matrix-এ Heap ব্যবহার করলে পুরো Matrix Flatten করে Sort না করেই Kth Smallest বা অন্য কোনো Rank-ভিত্তিক Answer বের করা যায়।

Pattern ৮ — Design Problems
