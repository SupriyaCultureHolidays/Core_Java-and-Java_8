MODULE 1: ADVANCED OOP & SOLID PRINCIPLES   (High priority)
--------------------------------------------------------------------------------
  [ ] SOLID Principles
      [ ] S - SRP: Single Responsibility Principle
              (one class = one responsibility = one reason to change)
      [ ] O - OCP: Open/Closed Principle (open for extension, closed for modification)
      [ ] L - LSP: Liskov Substitution Principle (child can replace parent)
      [ ] I - ISP: Interface Segregation Principle (small, specific interfaces)
      [ ] D - DIP: Dependency Inversion Principle (depend on abstractions)
  [ ] Composition vs Inheritance
  [ ] Association vs Aggregation vs Composition
  [ ] Abstraction vs Encapsulation (practical difference)
  [ ] Tight Coupling vs Loose Coupling
  [ ] Dependency Injection (concept)
  [ ] Immutable Class - how to create one
  [ ] Shallow Copy vs Deep Copy
  [ ] Object Cloning
  [ ] Builder Design Pattern basics

  Practice:
    1. Employee Management System using SOLID
    2. Hotel Booking System using Composition
    3. Create an immutable Employee class
    4. Implement Deep Copy and Shallow Copy

  SRP practice (done): split HotelBooking into HotelSearch, PriceCalculator,
  PaymentService, EmailService, BookingRepository.
  Next: BookingService that uses (gets injected with) these classes.
  Interview Q: PaymentService has validate/process/generateInvoice/refund/
  sendNotification - does it follow SRP? (Hint: No - invoice & notification
  are separate responsibilities.)
